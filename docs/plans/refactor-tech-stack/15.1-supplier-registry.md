### 1.3 Bảng `suppliers`

Convention cột theo repo: `String` + `JSON_VARIANT` từ `db/types.py`, audit `DateTime(timezone=True)`
+ `server_default=func.now()`, `is_active` mặc định true. Khác `partner_profiles` ở 3 điểm kernel:
`tenant_id` (K7), `created_by`/`updated_by` (K4), id sinh bằng `core/kernel/ids.py` (K6).

| Cột | Kiểu | Ghi chú |
| :-- | :-- | :-- |
| `id` | String(64) PK | `sup_` + uuid7 hex 12 — sortable theo thời gian tạo |
| `tenant_id` | String(64) NOT NULL, default `"capella"`, indexed | K7 — chỉ bảng module mới có |
| `name` | String(255) NOT NULL | Tên giao dịch |
| `name_normalized` | String(255) NOT NULL | lower + bỏ dấu + collapse space (helper thuần trong service, cùng thuật toán dedupe của `products` 15.2) |
| `legal_name` | String(255) NULL | Tên pháp lý trên hợp đồng/hóa đơn |
| `supplier_type` | String(24) NOT NULL | vocab §1.4 |
| `country` / `city` | String(64) NULL | Free-text; địa lý chuẩn hóa dùng cột dưới |
| `destination_id` | String(64) NULL, FK `destination_catalog` **ondelete RESTRICT** | FK chéo module hợp lệ (integrity, không JOIN) |
| `default_currency` | String(3) NOT NULL | Validate boundary ∈ `SUPPORTED_CURRENCIES` (import từ `core/rules/pricing_rules.py` — không định nghĩa lại) |
| `preferred_status` | String(16) NOT NULL, default `"standard"` | vocab §1.4 |
| `quality_tier` | String(16) NULL | vocab §1.4 |
| `contact_json` | JSONB NOT NULL, default `{}` | `{person, email, phone, whatsapp, zalo, website}` — tất cả optional |
| `payment_terms_json` | JSONB NULL | Phụ lục A.1 |
| `cancellation_policy_json` | JSONB NULL | Phụ lục A.2 |
| `child_policy_json` | JSONB NULL | Phụ lục A.3 |
| `bank_details_ref` | String(255) NULL | Con trỏ secure store — chốt #6 |
| `tax_code` | String(64) NULL | |
| `credit_terms_days` | Integer NOT NULL, default 0 | Số ngày công nợ |
| `internal_notes` | String(2000) NULL | Staff-only, không bao giờ ra public surface |
| `is_active` | Boolean NOT NULL, default true | |
| `created_by` / `updated_by` | String(128) NULL | ActorRef serialize `"{actor_type}:{actor_id}"` (vd `staff:info.capellatravel@gmail.com`) |
| `created_at` / `updated_at` | DateTime(timezone=True) | server_default now, onupdate now |

**Constraints & indexes**:

- `UniqueConstraint(tenant_id, name_normalized)` — dedupe key. Email KHÔNG unique
  (khác partner: nhiều supplier dùng chung email đặt phòng, hoặc không có email).
- `Index(is_active, name)` — phục vụ list mặc định.
- `Index(tenant_id, supplier_type)`, `Index(destination_id)` — phục vụ filter.

### 1.4 Vocabulary (Literal ở Pydantic, String ở DB — mirror cách partner xử lý `tier`)

- `supplier_type`: `direct | dmc | wholesaler | bedbank | ota | freelancer | gov | other`
- `preferred_status`: `preferred | recommended | standard | backup | do_not_use`
- `quality_tier`: `ultra_luxury | luxury | premium | standard | value`

Ba vocab này khai báo một lần trong `schemas/v2/supplier.py` dạng `Literal`, DB giữ String
(không CHECK constraint — nhất quán với toàn repo). `do_not_use` vẫn hiện trong list
(khác `is_active=false`): active nhưng bị cấm dùng là trạng thái nghiệp vụ, không phải soft-delete.

### 1.5 API surface — `/api/v2/suppliers`

Mirror 1-1 shape của partners (router → service → repository, `DbSessionDep` +
`EditorPrincipalDep`, commit ở router, `ValueError` → 409, not-found → 404):

| Operation | Method + Path | Ghi chú |
| :-- | :-- | :-- |
| List | `GET /api/v2/suppliers` | Query: `active=true\|false\|all`, `search` (name/legal_name/contact person — qua `name_normalized` cho name), `supplier_type`, `destination_id`, `limit` (1..200, default 100). Response `{items, total}` |
| Create | `POST /api/v2/suppliers` | 201; trùng `(tenant, name_normalized)` → 409 |
| Get | `GET /api/v2/suppliers/{supplier_id}` | 404 nếu không có |
| Update | `PUT /api/v2/suppliers/{supplier_id}` | Partial update schema (mọi field optional); đổi `name` → tính lại `name_normalized`, có thể 409 |
| Set status | `PATCH /api/v2/suppliers/{supplier_id}/status` | Body `{isActive: bool}` — mirror partner |

Schemas trong `schemas/v2/supplier.py` theo đúng khung partner:
`SupplierBaseSchema` → `SupplierCreateSchema` (`extra="ignore"`) / `SupplierUpdateSchema`
(all-optional) / `SupplierResponseSchema` (`from_attributes=True`, thêm `id`, `is_active`,
`created_at`, `updated_at`) / `SupplierListResponseSchema` `{items, total}`.
3 policy JSONB có sub-model Pydantic riêng (Phụ lục A) — nested validate, không `dict[str, Any]`.
Response **không** trả `bank_details_ref` đầy đủ giá trị nhạy cảm — nó vốn là ref nên trả nguyên,
nhưng `internal_notes` chỉ nằm trong response staff API này, không được map sang bất kỳ
public/brochure schema nào.

### 1.6 Service & repository — phân tầng trách nhiệm

- **Repository** (`supplier_repository.py`): query thuần — `list(filters) -> (rows, total)`,
  `get_by_id`, `get_by_normalized_name`, `insert`, `update`, `set_status`. Không business logic,
  không commit. Lỗi typed nếu cần thêm vào `repositories/errors.py` (15.1 chưa cần loại mới).
- **Service** (`supplier_service.py`): normalize name (hàm pure module-level, có test riêng),
  check dedupe → raise `ValueError` message rõ ràng, sinh id qua `core/kernel/ids.py`,
  gán `created_by/updated_by` từ ActorRef, map schema ↔ model. Nhận `ActorRef` trong chữ ký
  các hàm ghi ngay từ 15.1 (K4) — router dựng ActorRef từ `EditorPrincipalDep`
  (`actor_type="staff"`); sau này AI drafter truyền `actor_type="ai_agent"` mà không đổi chữ ký.
- **Router**: parse/validate/commit/HTTP mapping — không logic.

## Phụ lục A — Shape 3 policy JSONB (SSOT cho cả BE Pydantic lẫn FE types.ts)

Kế thừa Phụ lục B của 14.0, thu gọn cho MVP. Mọi field optional trừ khi ghi chú.

**A.1 `payment_terms_json`**
```
{ deposit_percent: int 0..100,
  deposit_due_days_after_confirm: int >= 0,
  balance_due_days_before_service: int >= 0,
  method: "bank_transfer" | "cash" | "card" | "other",
  note: str <= 500 }
```

**A.2 `cancellation_policy_json`**
```
{ tiers: [ { days_before_service_min: int >= 0,   # cận dưới của band, sort giảm dần
             penalty_percent: int 0..100 } ],      # 100 = mất toàn bộ
  no_show_penalty_percent: int 0..100 (default 100),
  note: str <= 500 }
```
Invariant validate: `tiers` không chồng band, `days_before_service_min` giảm dần
→ penalty tăng dần (một validator Pydantic, có unit test).

**A.3 `child_policy_json`**
```
{ bands: [ { age_min: int 0..17, age_max: int 0..17,
             charge_percent: int 0..100 } ],       # % giá người lớn
  infant_age_max: int 0..3,
  note: str <= 500 }
```
Invariant: band không chồng tuổi, `age_min <= age_max`.

> Ba shape này ở 15.1 là *default theo supplier*. 15.3 cho phép rate override cùng shape —
> đó là lý do sub-model Pydantic phải đặt ở file schema dùng chung được
> (`schemas/v2/supplier.py` export để `schemas/v2/rate.py` import lại sau này).

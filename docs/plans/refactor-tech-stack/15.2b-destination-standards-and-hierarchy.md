## 3. Backend Design — Tourism Hub

### 3.1 Sáu cột mới trên `destination_catalog` (tất cả nullable/có default — additive thuần)

| Cột | Kiểu | Ghi chú |
| :-- | :-- | :-- |
| `parent_id` | String(64) NULL, FK self ondelete RESTRICT | Cây thương mại. NULL = root (country) hoặc chưa phân loại |
| `destination_type` | String(16) NOT NULL, default `"city"` | vocab `country \| region \| province \| city \| sub_zone` — thêm vào `core/rules/catalog_vocab.py` (`DESTINATION_TYPE`), cùng nhà với vocab 15.2 |
| `country_code` | String(2) NULL | ISO 3166-1 alpha-2, uppercase validate |
| `iata_code` | String(3) NULL | Uppercase; **không unique** (nhiều hub chung sân bay: Hội An & Đà Nẵng → DAD) |
| `timezone` | String(64) NOT NULL, default `"Asia/Ho_Chi_Minh"` | IANA; validate qua `zoneinfo.available_timezones()` ở boundary |
| `merged_into_id` | String(64) NULL, FK self ondelete RESTRICT | Soft redirect. CHECK `merged_into_id != id` |

Index mới: `ix_destination_catalog_parent` (`parent_id`), `ix_destination_catalog_type_active`
(`destination_type, is_active`). Không thêm `tenant_id` — destination là shared reference data
(quyết định tường minh: khác K7, vì taxonomy địa lý không thuộc về tenant nào).

Bất biến cây (validator ở service, không phải DB): parent phải có `destination_type` "cao hơn"
theo thứ tự `country > region > province > city > sub_zone` (cho phép nhảy bậc — city treo thẳng
vào country với đảo quốc); chống cycle bằng walk-up có max depth 6; row đã có `merged_into_id`
không được làm parent của row mới.

### 3.2 Vòng đời sáp nhập — operation `merge`, không phải UPDATE thường

`POST /api/v2/destinations/{id}/merge` body `{targetId}` — quyền `require_quote_admin`,
nguyên tử 1 transaction:

1. Validate: target tồn tại, active, chưa merged; không tự merge; không tạo chuỗi vòng.
2. **Repoint alias có chọn lọc**: alias của A chuyển sang B, **bỏ qua** alias đụng unique toàn cục
   (mìn số 1 từ audit — không xóa mù, không crash); thêm `canonical_name` + `slug` của A thành
   alias mới của B (skip nếu đụng).
3. Set `merged_into_id = B`, `is_active = false` trên A. **Không đụng** slug, media_prefix,
   slug chain, không DELETE (chốt #3, #4).
4. **Không repoint FK** của products/suppliers/accommodations — id bất biến, dữ liệu cũ đứng yên.
   Repository thêm helper `effective_destination_id(id)` (follow chain, max depth 3) cho 15.4
   dùng khi roll-up.
5. Emit outbox `catalog.destination.merged` `{source_id, target_id}` — mirror vào
   notification EventType (đúng luật K5/E12).

Resolver học redirect ở **cả 3 tầng** của `DestinationRepository.resolve()`: kết quả trỏ tới row
có `merged_into_id` → follow chain rồi trả row đích; tầng fuzzy loại row merged khỏi scan (vá
luôn điểm hiệu năng audit chỉ ra). `search()` mặc định loại row merged; `matched_from` ghi
`"merged:{old_slug}"` để FE hiện gợi ý "đã sáp nhập vào…".

### 3.3 Alias resolver nâng cấp

- Giữ nguyên 3 tầng + thuật toán fuzzy (không viết lại — chỉ thêm merged-filter + follow).
- Seed bổ sung alias 2 chiều cho các cặp sáp nhập đã biết (đợt sắp xếp đơn vị hành chính VN):
  tên tỉnh cũ → hub mới, dạng **data trong `destination_catalog_seed.py`**, đi qua đúng đường
  `upsert` non-destructive. Danh sách cụ thể là task data khi implement, không thuộc schema design.
- `mapping_version` (cột chết audit tìm ra) được dùng lại: bump `"resolver-v2"` khi row được
  seed/merge theo chuẩn mới — công tắc debug miễn phí, không thêm cột.

### 3.4 Tuyến 2 đầu trên `products` (chốt #8)

- Cột mới `origin_destination_id` String(64) NULL, FK `destination_catalog` ondelete RESTRICT.
  Ngữ nghĩa: `destination_id` = điểm ĐẾN/nơi phục vụ (giữ nguyên nghĩa cũ); origin chỉ được set
  khi `category ∈ {transportation, flights}` (validator boundary, cùng khuôn với luật
  `property_id` của 15.2).
- **Rebuild unique index của products**: `uq_products_tenant_destination_category_title_supplier`
  thêm thành phần `coalesce(origin_destination_id,'')` — cùng title "Xe 16 chỗ" cho 2 chặng khác
  nhau là 2 product hợp lệ. Đây là thay đổi unique index phải xong TRƯỚC khi 15.3 FK `rates` vào
  products — lý do tồn tại của cả bước 15.2b.
- HDV suốt tuyến / xe nhiều chặng phức tạp hơn 2 đầu: **không** mô hình hóa ở catalog — đó là
  bài toán của service_lines per-day (15.4). Catalog chỉ giữ chuẩn 2 đầu.

### 3.5 API surface

Sửa 5 chỗ audit đã khoanh (model → repo kwargs (keyword-only, non-breaking) → `_serialize_destination`
→ `DestinationCatalogRequest` (field mới **có default** — 2 client PUT/POST hiện có không gãy)

| Operation | Method + Path | Ghi chú |
| :-- | :-- | :-- |
| Merge | `POST /api/v2/destinations/{destination_id}/merge` | §3.2 — +1 manifest op |
| List (mở rộng) | `GET /api/v2/destinations` | +query `types` (csv ∈ DESTINATION_TYPE; **default loại `country,region`** để dropdown itinerary hiện trạng không đổi hành vi), `parentId` (lọc con trực tiếp + roll-up qua helper), giữ nguyên các param cũ |

GET response thêm: `parentId`, `destinationType`, `countryCode`, `iataCode`, `timezone`,
`mergedIntoId` — camelCase theo serializer hiện hành.

## 4. R2 Media Storage Invariant (chốt #4)

Audit xác nhận: destination R2 path **recompute lúc đọc** từ `country_slug/region_slug/
province_slug/slug`; accommodation path **đóng băng** trong `asset_prefix`. Nếu hierarchy làm
thay đổi slug chain → media destination tự di chuyển (404) trong khi media accommodation đứng
yên — desync tồi tệ nhất có thể.

Vô hiệu hóa bằng 3 quy tắc, **không sửa một dòng nào của `services/media_locations.py`**:

1. `parent_id` là metadata thuần — không có code nào derive `country_slug/region_slug/
   province_slug` từ cây. Hai hệ tọa độ (cây thương mại vs slug chain storage) tách rời vĩnh viễn.
2. Slug chain + `media_prefix` trở thành **storage identity đóng băng** sau khi destination có
   media: API update từ chối đổi 3 cột `*_slug` khi đã tồn tại media object trỏ vào destination
   (check qua hàm public của media repository — không JOIN chéo); message hướng dẫn dùng
   `media_prefix` override nếu thật sự cần chuyển nhà (chuyển nhà = copy R2 thủ công, ngoài scope).
3. Merge (§3.2) không đụng bất kỳ trường storage nào của A — ảnh cũ sống nguyên chỗ cũ, brochure
   cũ giữ nguyên link.

Known issue ghi nhận, ngoài scope: `media_locations.destination_location` đòi đủ 4 slug (raise)
trong khi serializer join phần non-null — 2 công thức default prefix có thể lệch. Không sửa ở
15.2b (đụng vùng media đang chạy); mở change request riêng.

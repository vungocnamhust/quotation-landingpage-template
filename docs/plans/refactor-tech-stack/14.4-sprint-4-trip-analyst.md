## 3. Chi tiết kỹ thuật

### 3.1 Vấn đề cụ thể

Cùng 4 pax, `rooms` khác nhau hoàn toàn:

| Cùng 4 pax | rooms |
| :-- | :-- |
| 2 couple | 2 Double |
| 2A + 2C (8, 12) | 2 Connecting |
| 4 bạn nữ | 2 Twin |
| 2A + 2C (2, 4) | 1 Double + extra bed |

Khác biệt nằm trong `special_requirements` (2000 ký tự văn xuôi), `children_details`, `kid_ages`, `market`. Không rules engine nào giải được.

### 3.2 Schema

Xem `§2.1` của [14-ai-service-drafter-and-costing.md](./14-ai-service-drafter-and-costing.md). Điểm bắt buộc:

- `model_config = ConfigDict(extra="forbid")` trên **mọi** model.
- **Không** trường tiền nào. `budget` không thuộc `TripProfile`.
- `unknowns: list[str]` — không chắc thì ghi vào đây, **không đoán bừa**.
- `reasoning: str` viết cho sale đọc.

### 3.3 Agent

```python
# services/trip_analyst.py
analyst = Agent(
    model=llm_client.get_model(),                 # điểm construct provider DUY NHẤT
    output_type=TripProfile,
    system_prompt=get_prompt_loader().build_prompt_bundle("trip_analyst").system,
)
```

Output không hợp lệ ⇒ Pydantic AI retry ⇒ vẫn sai ⇒ raise `TripAnalysisError`, **persist nothing** (theo pattern `ContentGenerationError`).

### 3.4 Fallback khi analyst lỗi

```python
def fallback_profile(req) -> TripProfile:
    """Dựng từ rooming_heuristic_service đã có sẵn. confidence = 0."""
```

Banner UI: *"Chưa phân tích được — kiểm tra thủ công"*. **Không bao giờ chặn luồng.**

### 3.5 Lưu ở đâu

`quotation_documents.document_json.trip_profile` của baseline language — **không bảng mới**. Vì profile làm thay đổi costing, `:analyze`/`PATCH` phải CAS `CS1.costing_revision` và save document trong cùng transaction; không dùng revision per-language làm costing concurrency token. Nếu document concurrently đổi, trả 409/reload thay vì ghi đè.

### 3.6 Endpoint

| Method | Path | Hành vi |
| :-- | :-- | :-- |
| `POST` | `/api/v2/quotations/{id}/trip-profile:analyze` | Chạy analyst, ghi document, trả profile |
| `PATCH` | `/api/v2/quotations/{id}/trip-profile` | Sale sửa ⇒ ghi + **tính lại toàn bộ `service_lines`** |

`PATCH` phải recompute vì `room_config` đổi ⇒ `rooms` đổi ⇒ `qty` mọi dòng Accommodation đổi.

### 8.1 `room_type` phải suy ra được `occupancy_basis`

14.0 §2.5 (`rate_price_lines`) chọn giá khách sạn theo khoá
`(price_for='room', occupancy_basis, unit)` với `occupancy_basis ∈ {sgl, dbl, twn, trpl, quad, na}`.

`TripProfile.room_config` là **nguồn duy nhất** biết đoàn ngủ thế nào. Nếu `room_type` là văn bản tự do
(*"Connecting"*, *"phòng nối"*, *"Double có kê thêm giường"*), Phase 2 sẽ không join được price line và
phải viết một tầng đoán chữ — đúng loại nợ 14.0 tồn tại để tránh.

```python
# schemas/trip_profile.py
RoomType = Literal["single", "double", "twin", "triple", "quad", "connecting", "suite", "other"]

class RoomAllocation(BaseModel):
    model_config = ConfigDict(extra="forbid")
    room_type: RoomType
    count: int
    occupants: list[str]
    extra_beds: int = 0
    note: str = ""
```

Kèm một hàm **pure** trong `core/rules/` (không nằm trong schema):

```python
OCCUPANCY_BY_ROOM_TYPE = {
    "single": "sgl", "double": "dbl", "twin": "twn",
    "triple": "trpl", "quad": "quad",
    "connecting": "dbl",     # cụm nối = nhiều phòng dbl, count đã phản ánh số phòng
    "suite": "dbl", "other": "na",
}

def derive_occupancy_basis(room_type: str) -> str:
    return OCCUPANCY_BY_ROOM_TYPE.get(room_type, "na")
```

Sprint này **chưa dùng** `derive_occupancy_basis` (chưa có catalog). Nó chỉ cần tồn tại + có test phủ 100%
để Phase 2 không phải sửa `TripProfile` — vốn là schema đã ràng vào prompt và 10 fixture.

> Prompt `trip_analyst.yaml` phải liệt kê đúng 8 giá trị `RoomType` và bảo LLM chọn giá trị gần nhất,
> ghi mô tả gốc vào `note`. Không để LLM tự chế tên phòng.

### 8.2 `child_ages` phải ở cấp profile

`child_policy_json` (14.0 §Phụ lục B.3) phân định infant/child theo **tuổi từng bé**
(`infant_age_to: 1`, `child_age_to: 11`), và `age_reference_date: travel_date`.
`children: int` không đủ. `TripProfile` giữ `child_ages: list[int]` — dữ liệu này đã có sẵn trong
`QuoteRequest.kid_ages`, chỉ cần không đánh rơi khi normalize.

### 8.3 Không thêm gì khác

`TripProfile` vẫn **không có trường tiền** (done criterion #1). Supplier, rate, markup đều nằm ngoài profile.

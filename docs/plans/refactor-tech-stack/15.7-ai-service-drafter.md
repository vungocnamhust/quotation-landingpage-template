> (không tạo `ai_runs` — đã có).
>
> **Nguyên tắc tối thượng**: AI không có đường ghi mới. Drafter ghi `service_lines` qua đúng
> service functions 15.4 (`source="ai_draft"`, ActorRef `ai_agent` — K4 trả giá trước cho đúng
> khoảnh khắc này); mọi validator/CAS/idempotency của 15.4 áp lên AI y như lên người.

**Một câu**: TripAnalyst (0 tool, văn xuôi → `TripProfile`, sale review 1 lần) → ServiceDrafter
(1 call/ngày song song, tools read-only từ kho chung, output **chỉ có ID + lý do — schema không
có một field tiền nào**) → server resolve giá bằng `rate_selection` 15.3 → ghi qua costing 15.4.
Ảo giác giá bị triệt tiêu bằng cấu trúc, không phải bằng kiểm tra sau.

## 0. Scope chốt

| # | Chốt | Ràng buộc thi hành |
| :-: | :-- | :-- |
| P1 | **Platform mỏng, 5 file, không framework tự chế** | `services/ai_platform/` chỉ gồm: agent factory (gói `llm_client.get_model()` + `PromptLoader` + typed output + retries — pattern `section_content_generator` được chuẩn hóa, KHÔNG viết lại runtime), deps read-only, toolset catalog, guardrails, run-log. Không plugin system, không tool auto-discovery, không config engine |
| P2 | **Một kho tools read-only dùng chung** | `toolsets/catalog.py` — mọi agent tương lai cần tra catalog dùng chung 7 tool (§1.4); tool mới = thêm hàm vào file này. Deps chỉ chứa hàm query public của repositories, **không session ghi** (read-only theo cấu tạo, không theo quy ước) |
| P3 | **Một bảng run-log chung `ai_runs`** | Mọi agent run (mọi loại) ghi vào một bảng: agent_name, anchor, status, stats, budget. Append-only. Đo được mọi agent bằng một query |
| P4 | **Guardrails là hạ tầng, không phải phép lịch sự** | `AllowlistRecorder` (mọi id tool trả ra), `OutputValidator` (id ngoài allowlist → retry ≤2 → bỏ + flag, không exception xuyên run), `RunBudget` (trần call/token cứng — vượt là dừng, giữ phần đã xong) — nằm ở platform, agent nào cũng bị áp |
| 1 | **Schema output Drafter không có tiền** | `ServiceDraft` không chứa amount/price/currency — bịa giá bất khả thi cấu trúc. Grep schema: `_minor\|price\|amount` rỗng |
| 2 | **Server resolve giá, rate thiếu = thông tin** | Giá luôn từ `rate_selection.select_rates` + `pick_price_line` (15.3, pure). Không rate → line vẫn tạo, `rate_missing=true`, cost=0; conflict (T6) → sale chọn, AI không quyết |
| 3 | **Văn xuôi khách không chạm tầng có tool** | Text thô chỉ vào TripAnalyst (0 tool). Drafter nhận day-context cấu trúc từ `TripProfile` — injection từ khách bị cô lập ở tầng không có gì để chiếm |
| 4 | **Human gate giữa 2 tầng** | `TripProfile` phải được sale review/sửa trước khi tầng 2 chạy. Không có endpoint chạy thẳng 2 tầng |
| 5 | **Không taxonomy mới** | `TripProfile` tái dùng vocab sẵn (`OCCUPANCY_BASIS`, `QUALITY_TIER`, `CATEGORY`) — bài học T5 |
| 6 | **Không sửa module đã đóng ngoài 2 điểm additive khai báo** | Cột `ai_meta_json` trên `service_lines` + affordance trong `components/quotation-costing/` |

### 1.4 Kho tools chung — `toolsets/catalog.py` (7 tools, read-only, SQL-filtered, ≤8 dòng/lần)

Nhóm A — Drafter dùng (15.7):

| Tool | Tham số | Ruột (tái dùng qua hàm public repo) | Trả về |
| :-- | :-- | :-- | :-- |
| `search_accommodations` | `destination_id, quality_tier, room_config, meal_plan?` | product_repo category=accommodation + roll-up cây 15.2b (`effective_destination_id`) | ≤8 `{product_id, title, property_id, tier, room_types[]}` |
| `search_transport` | `route_from, route_to, pax, comfort?` | filter `origin_destination_id` (G2) + `seat_capacity ≥ pax` | ≤8 candidates |
| `search_activities_and_dining` | `destination_id, tags?, pace, mobility` | category ∈ {experience, meal, ticket}; mobility lọc `physical_level` | ≤8 candidates |
| `resolve_applicable_rates` | `product_id, service_date, occupancy, pax` | wrapper `rate_selection` + `pick_price_line` (15.3) | `{tariff_id, price_line_id, has_conflict, rate_missing, price_band: low\|mid\|high}` — **không amount**; band server tính để AI cân budget mà không thấy số |

Nhóm B — Ingestion Co-Pilot dùng (15.8), khai báo sẵn cùng file:

| Tool | Trả về |
| :-- | :-- |
| `find_supplier(name_text)` | match `name_normalized` → ≤3 `{supplier_id, name, destination, is_active}` |
| `find_products(supplier_id?, destination_id?, category?, title_text?)` | ≤8 candidates theo dedupe key 15.2 |
| `find_active_rates(product_id, window_from, window_to)` | ≤5 `{tariff_id, season, validity, lifecycle}` — phát hiện xung đột mùa giá; **không amount** |

Bất biến chung mọi tool: `tenant_id` từ deps (không từ LLM) · tự append id trả ra vào
`AllowlistRecorder` · `service_date`/window nhận LocalServiceDate đã quy tz (quy tắc 15.3 §0.1)
— tool tz-agnostic · không tool nào trả số tiền.

### 1.5 Hai schema (nhắc gọn — chi tiết như bản brainstorm đã chốt)

- **`TripProfile`**: `archetype` (8 giá trị) · `party` · `room_config: list[RoomAllocation
  {room_type ∈ OCCUPANCY_BASIS, count, extra_bed, occupants_note}]` · `mobility` · `pace` ·
  `dietary[]` · `quality_tier` · `guide_need + languages[]` · `special_flags[]` (trích
  **nguyên văn**, không diễn dịch) · `confidence_notes[]` (điều KHÔNG chắc — FE render đỏ).
  Fallback Analyst lỗi: build tối thiểu từ `rooming_heuristic_service` (deterministic),
  run đánh dấu `fallback_used`.
- **`ServiceDraft`** (per-day trong `DayDraftResult`): `category`/`subcategory` ∈ vocab ·
  `product_id` (∈ allowlist) · `tariff_id?`/`price_line_id?` · `qty_unit`/`qty_time` ·
  `selection_reason ≤160` bắt buộc · `flags[] ∈ {rate_missing, rate_conflict,
  has_supplement_in_range, needs_manual}`.

### 1.6 API — 3 operations (`routers/v2/ai_drafter.py`)

Auth theo sheet (request-anchored → editor; quotation-anchored → `require_owned_quotation`)
qua `api/runtime.py` callbacks.

| Operation | Method + Path | Ghi chú |
| :-- | :-- | :-- |
| Analyze | `POST /api/v2/costing-sheets/{sheet_id}/ai/analyze` | + `Idempotency-Key`. Trả `{runId, tripProfile, fallback_used, confidence_notes}`. Không ghi line |
| Draft | `POST /api/v2/costing-sheets/{sheet_id}/ai/draft` | Body `{runId, tripProfile (bản sale đã sửa), dayNumbers?}` + `baseCostingRevision` + `Idempotency-Key`. Per-day song song, trần `RunBudget = số ngày + 2` calls; mỗi day xong ghi lines qua `costing_service.create_line` (ActorRef ai_agent, `ai_meta_json`); day fail → `days_failed`, run `partial`. Đồng bộ trong request (MVP); nâng background không đổi API shape |
| List runs | `GET /api/v2/costing-sheets/{sheet_id}/ai/runs` | Từ `ai_runs` — đo tỷ lệ sale giữ nguyên dòng AI |

## 4. Exit Gate

1. **Kịch bản thật**: request văn xuôi 2000 ký tự (gia đình 3 thế hệ, 5 ngày HN–Hạ Long–Ninh
   Bình) → Analyze → sale sửa room_config → Draft → grid đầy lines badge AI + reason đọc được;
   ≥1 dòng `rate_missing` hiện banner; Swap 1 click; Apply 15.5 chạy bình thường trên sheet có
   dòng AI.
2. **Zero-hallucination kiểm bằng máy**: introspection zero-money + allowlist fail-closed +
   grep không đường nào từ output LLM tới `unit_cost_minor` ngoài `rate_selection` server-side.
3. **Platform sẵn sàng cho consumer thứ hai**: 15.8 dùng được `build_agent` + toolset nhóm B +
   `ai_runs` + guardrails mà không sửa file platform nào (kiểm khi 15.8 implement — điều kiện
   nghiệm thu kiến trúc của bước này).
4. Toàn bộ test §3 xanh; `git diff` đúng 2 điểm additive khai báo + module mới; kernel vẫn 3
   file; một provider construction site duy nhất (grep `OpenAIChatModel` ngoài `llm_client.py`

## 5. Những gì 15.7 cố tình KHÔNG làm

| Không làm | Vì | Đi đâu |
| :-- | :-- | :-- |
| Migrate `section_content_generator` sang platform | Platform phải chứng minh trước; hợp nhất là refactor riêng | Change request sau 15.8 |
| Tool registry động / plugin system | 2 consumer + 7 tool = 1 file Python là đủ (P1) | Khi ≥4 agent thật |
| Auto-cộng supplement vào line | Đổi engine 15.4 — không trộn vào AI | `costing_rules` nâng cấp riêng |
| Chạy thẳng 2 tầng không review | Human gate là thiết kế | Không bao giờ |
| AI tự tạo product/rate khi thiếu | Bài của 15.8 với human gate riêng | 15.8 |
| Vector DB / embeddings | SQL-filter đủ cỡ agency | Khi catalog >10k products |
| Margin optimizer | Sell là của sale (15.5) | Không bao giờ (by design) |

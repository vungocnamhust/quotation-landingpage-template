### 0.1 Ranh giới `accommodation_profiles` — không thuộc Design, không thuộc Catalog

`accommodation_profiles` **không phải "một phần của Design"**. Nó là bounded context content độc
lập (ảnh/intro/room_type — xem AGENTS.md), bị **hai module tiêu thụ song song, chỉ qua đọc bằng
ID**, không ai sở hữu nó:

```text
                    accommodation_profiles (content, độc lập, bất biến)
                     ▲                                    ▲
                     │ đọc qua accommodation_id            │ đọc qua property_id (FK, R4/T10)
                Quotation/Design                     Product Catalog (15.2, §1.4)
          (brochure hiển thị ảnh/intro)        (product category=accommodation mượn content)
```

Hệ quả thi hành: `components/display/**` không bao giờ biết `products` tồn tại; `products`/Costing
không bao giờ biết `quotation facts` tồn tại. `property_id` trên `products` là quan hệ **đọc**,
không phải kế thừa hay sở hữu — xóa/deactivate một product không ảnh hưởng
`accommodation_profiles`, và ngược lại. Đây là lý do FK dùng `ondelete RESTRICT` chứ không
`CASCADE`: xóa property đang được product tham chiếu phải bị chặn tường minh, không âm thầm
cascade sang catalog.

### 1.3 Vocab — `core/rules/catalog_vocab.py`

- `CATEGORY` (frozenset, 10): `accommodation | transportation | ticket | flights | guide |
  guide_expense | experience | meal | visa | others` — lấy nguyên văn từ
  `docs/service-picker-costing-engine.md #D0`, không thêm bớt.
- `UNIT` (frozenset): `room | person | vehicle | group | ticket | flight_seat | visa_case | set`
  — mở rộng bằng cách thêm vào file này, không hardcode chỗ khác.
- `TIME_BASIS` (frozenset): `night | day | trip`.
- `DEFAULT_CHARGE_UNIT_BY_CATEGORY` (mapping → `(unit, time_basis)`), ví dụ:
  `accommodation → (room, night)`, `transportation → (vehicle, day)`, `guide → (group, day)`,
  `ticket/experience/meal → (person, trip)`, `flights → (person, trip)`, `visa → (person, trip)`,
  `guide_expense → (group, day)`, `others → (set, trip)`.
  Đây là **default gợi ý khi tạo product** — giá trị lưu trên từng row luôn tường minh,
  không suy runtime.
- `SUBCATEGORY_BY_CATEGORY` (mapping `Category → frozenset[str]`, vocab **đóng**, đầy đủ ở
  Phụ lục B): mỗi category có tập subcategory cố định, luôn kèm 1 giá trị `other_*` làm van an
  toàn. Khác với `category_attributes` (Phụ lục A — thuộc tính mô tả tự do như `room_type`,
  `seat_capacity`): subcategory trả lời "đây là loại dịch vụ gì" (Hotel vs Resort vs Villa),
  attributes trả lời "dịch vụ này có đặc điểm gì" (SGL/DBL, số ghế…) — không gộp hai khái niệm.
- Vocab được Pydantic schema import làm `Literal`/validator; FE mirror thủ công trong
  `components/product/types.ts` (theo tiền lệ `destinationRules.ts` mirror
  `core/rules/destination_rules.py`) — có comment 2 đầu trỏ về nhau.

### 1.4 Bảng `products`

Kernel columns như 15.1: `tenant_id` (K7), `created_by`/`updated_by` (K4), id `prd_` + uuid7 (K6).

| Cột | Kiểu | Ghi chú |
| :-- | :-- | :-- |
| `id` | String(64) PK | `prd_` + uuid7 hex 12 |
| `tenant_id` | String(64) NOT NULL, default `"capella"`, indexed | |
| `supplier_id` | String(64) NULL, FK `suppliers` **ondelete RESTRICT** | Chốt #4. RESTRICT: không xóa supplier còn product — supplier chỉ soft-deactivate |
| `property_id` | String(64) NULL, FK `accommodation_profiles` ondelete RESTRICT | Chỉ có nghĩa với `category="accommodation"` (validator boundary); R4/T10 |
| `destination_id` | String(64) NOT NULL, FK `destination_catalog` ondelete RESTRICT | Product luôn gắn điểm đến (Tourplan: Location là phần đầu của Option code) |
| `category` | String(24) NOT NULL | ∈ CATEGORY — validate boundary, DB giữ String (nhất quán repo) |
| `subcategory` | String(48) NULL | ∈ `SUBCATEGORY_BY_CATEGORY[category]` (Phụ lục B) — vocab đóng, validate boundary theo đúng category đã chọn (không phải union phẳng của cả 10 category) |
| `subcategory_note` | String(120) NULL | Chỉ có ý nghĩa khi `subcategory` kết thúc bằng `other_*` — mô tả tự do để không mất thông tin khi rơi vào nhóm "khác". Không ràng buộc DB, chỉ convention |
| `supplier_product_name` | String(255) NULL | SOURCE FACT — immutable sau khi tạo (chốt #6) |
| `title` | String(255) NOT NULL | NORMALIZED FACT — tên hiển thị |
| `title_normalized` | String(255) NOT NULL | Cùng thuật toán normalize với 15.1 |
| `unit` | String(32) NOT NULL | ∈ UNIT |
| `time_basis` | String(16) NOT NULL | ∈ TIME_BASIS — E4, cột riêng |
| `default_min_pax` / `default_max_pax` | Integer NULL | Validator: min ≤ max khi cả hai có |
| `category_attributes` | JSONB NOT NULL default `{}` | Khóa gợi ý theo category (Phụ lục A); giá trị scalar only |
| `is_active` | Boolean NOT NULL default true | |
| `created_by` / `updated_by` / `created_at` / `updated_at` | như 15.1 | |

**Dedupe & indexes**:

- Unique **functional index**: `(tenant_id, destination_id, category, title_normalized,
  coalesce(supplier_id, ''))` — bắt buộc dùng `coalesce` vì `supplier_id` nullable
  (Postgres mặc định coi 2 NULL là khác nhau → 2 bản ghi trùng vẫn insert được).
  Expression index chạy được trên cả Postgres lẫn SQLite (test target).
  Service vẫn check dedupe trước để trả 409 message tử tế thay vì IntegrityError.
- `Index(tenant_id, destination_id, category, is_active)` — query chính của picker
  ("dịch vụ loại X tại điểm đến Y").
- `Index(supplier_id)`, `Index(property_id)`.

### 1.5 API surface — `/api/v2/products`

Mirror khung partners/suppliers (commit ở router, ValueError → 409, 404 chuẩn):

| Operation | Method + Path | Ghi chú |
| :-- | :-- | :-- |
| List | `GET /api/v2/products` | Query: `active`, `category`, `destination_id`, `supplier_id`, `property_id`, `search` (qua title_normalized), `limit` (1..200, default 100). Response `{items, total}` |
| Create | `POST /api/v2/products` | 201; thiếu `unit`/`time_basis` → service điền từ `DEFAULT_CHARGE_UNIT_BY_CATEGORY`; trùng dedupe key → 409 |
| Get | `GET /api/v2/products/{product_id}` | |
| Update | `PUT /api/v2/products/{product_id}` | Partial; từ chối sửa `supplier_product_name` (422 nếu payload chứa và khác giá trị cũ — không silent-ignore để sale biết field bất biến); đổi `title`/`category`/`destination_id`/`supplier_id` → re-check dedupe |
| Set status | `PATCH /api/v2/products/{product_id}/status` | `{isActive: bool}` |

Validator boundary trong `schemas/v2/product.py` + service:

1. `category` / `unit` / `time_basis` ∈ vocab (Literal).
2. `subcategory` (khi có) ∈ `SUBCATEGORY_BY_CATEGORY[category]` — sai vocab của đúng category đó
   → 422 kèm danh sách hợp lệ trong message (sale không phải đoán).
3. `subcategory_note` chỉ chấp nhận khi `subcategory` là `other_*`; set note mà subcategory không
   phải `other_*` → 422 (tránh dữ liệu mồ côi).
4. `property_id` chỉ được set khi `category == "accommodation"`; ngược lại 422.
5. `property_id` và `destination_id` phải cùng destination (service check qua
   `AccommodationRepository` sẵn có — gọi hàm public, không JOIN).
6. `category_attributes`: `dict[str, str | int | bool]`, ≤ 20 keys, key snake_case ≤ 48 ký tự —
   loose validation, khóa gợi ý ở Phụ lục A không ép cứng (tránh over-normalize ở MVP).

### 1.6 Đồng bộ taxonomy với Gate 5 (`service_candidate_rules.py`)

Hiện `ServiceType` có 6 giá trị (`accommodation, rail, cruise, transport, experience, guide`)
**lệch** với 10 category — đây chính là loại taxonomy drift mà plan 14 từng cảnh báo (§1.2 T5).
Xử lý trong 15.2:

1. Grep xác nhận `ServiceType`/`ServiceCandidate` chưa có call site nào ngoài chính file đó
   (theo khảo sát 2026-08-27: đúng là placeholder chưa dùng). Nếu grep ra call site mới → dừng,
   báo cáo trước khi sửa.
2. Đổi `ServiceType` thành đúng 10 giá trị của `CATEGORY`, import từ `catalog_vocab.py`
   (rail/cruise trở thành `subcategory` của `transportation` — đúng cách Tourplan xử lý
   bằng Service Type code table + option code).
3. `ServiceCandidateEvaluator` Protocol **giữ nguyên chữ ký, chưa hiện thực** — evaluator là
   bài toán ranking lúc costing (15.4 chọn tay, 15.7 AI chọn). 15.2 chỉ đảm bảo repository
   có hàm search đủ dùng cho evaluator sau này (`list` với filter category + destination chính
   là nó).

## Phụ lục B — `SUBCATEGORY_BY_CATEGORY` (vocab đóng, SSOT tại `catalog_vocab.py`)

Nguồn: danh sách nghiệp vụ do user chốt. Slug = label lowercase, khoảng trắng/`/`/`-` →`_`, bỏ
ký tự đặc biệt. **Một sửa so với bản gốc**: category `guide` trong yêu cầu gốc không có tùy chọn
"Other" — 9/10 category còn lại đều có `other_*` làm van an toàn (bất biến §0 chốt #7 và §3 test).
Thêm `other_guide` để nhất quán và tránh việc guide loại lạ (vd hướng dẫn viên lặn biển,
guide chuyên biệt chưa liệt kê) không đại diện được. Nếu không đồng ý, xóa dòng đó khi implement —
nhưng khi đó cần nới lỏng bất biến "mọi category có other_\*" ở §3.

### 1.3 Manifest cho từng ca — theo đúng format hiện hành

Mỗi file thêm 1 entry `cases[]` trong `manifest.json` (format đã có, không đổi schema):
`category_focus` · `expected` (`supplier_present`, `products_min`, `rate_groups_min`,
`unresolved_min`, `requires_clarification`) · `scripted_answers` (`{target_path_suffix:
answer}`) cho các clarification dự kiến. Quy tắc viết:

- `expected` đặt **cận dưới thận trọng** (products_min ≤ số thật) — corpus test là guard chống
  regression, không phải exact-match với LLM.
- Trap `multi_supplier` và `contact_price` **cố ý không có** scripted_answers đủ — hành vi đúng
  của seeding là dừng báo cáo; manifest thêm `"expect_seed_stops": true` nếu cần đánh dấu
  (mở rộng manifest là thêm key, test hiện hành bỏ qua key lạ).
- Cập nhật `corpus_version` = `"2"` và sửa `note` bỏ chữ SYNTHETIC khi đợt thay thế hoàn tất.

### 1.4 Definition of Done mỗi ca

```bash
PYTHONPATH=. pytest tests/test_ingestion_corpus.py -m integration -q
```
xanh cho toàn corpus (test này gọi LLM thật — chạy chọn lọc, không nằm trong CI mặc định).

## 2. Deliverable 2 — Chạy seeding tới đích

### 2.1 Runbook

```bash
# 1. Môi trường dev/staging (KHÔNG production), DB đã ở head _45+
docker compose -f docker-compose.local.yml up -d postgres migrate app

# 2. Chạy seed toàn corpus
ALLOW_INGESTION_SEED=1 PYTHONPATH=. python -m scripts.seed_catalog_via_ingestion

# 3. Đọc báo cáo script: N committed / M stopped (trap) — trap PHẢI nằm ở stopped
```

### 2.2 Verify sau lần chạy 1 (SQL — số nghiệm thu)

```sql
SELECT 'suppliers', count(*) FROM suppliers WHERE is_active
UNION ALL SELECT 'products_with_active_rate',
  count(DISTINCT p.id) FROM products p JOIN rates r ON r.product_id = p.id
  AND r.lifecycle_status = 'active'
UNION ALL SELECT 'rates_active', count(*) FROM rates WHERE lifecycle_status='active'
UNION ALL SELECT 'batches_committed', count(*) FROM ingestion_batches WHERE status='committed'
UNION ALL SELECT 'rate_sources', count(*) FROM rate_sources;
```

Đạt khi: `products_with_active_rate ≥ 25` · mỗi batch committed có `rate_sources` tương ứng ·
các ca trap dừng ở `needs_clarification`/unresolved (đếm `ingestion_batches` status).

### 2.3 Verify idempotency (lần chạy 2 — bắt buộc)

Chạy lại y nguyên lệnh seed → nghiệm thu: **0 supplier/product/rate mới** (so 2 lần đếm SQL);
báo cáo script toàn `skip_duplicate`/`update`. Đây là bài nghiệm thu chống trùng của 15.8 chạy
miễn phí — fail ở đây là bug resolution, mở fix riêng.

### 2.4 Xử lý ca dừng

Ca dừng đúng thiết kế (trap) → để nguyên làm bằng chứng. Ca dừng ngoài dự kiến → phân loại:
thiếu scripted answer (bổ sung manifest, chạy lại) vs extractor/parser yếu thật (ghi thành bug
15.8, KHÔNG nới expected để ép xanh).

Core Domain Rule Frontend Architecture / Domain Invariants

4-Layer Bidirectional Reconciler & Canonical Adapter Engine

Bản Chất Kỹ Thuật (What it is)

Kiến trúc xử lý logic nghiệp vụ phân tách thành 4 tầng khép kín: (1) Pure Domain Reconcilers (hàm thuần túy, 0 React dependencies, 100% deterministic), (2) Canonical Adapters (chuyển đổi 2 chiều giữa UI state và Domain model không làm xáo trộn schema gốc), (3) Facade Updaters / Hooks (single-pass state transformations), và (4) React UI (chỉ gọi 1 dòng Facade Updater hoặc Adapter Reconciler, cấm tính toán inline).

Mục Đích & Rationale (Why we use it)

Giải quyết triệt để bài toán đồng bộ dữ liệu liên đới phức tạp (Temporal Trip, Stays Clustering, Tri-Pricing, Party Composition). Loại bỏ hoàn toàn lỗi Data Drift, Race Conditions, và việc lạm dụng useEffect gây re-render vô tận hoặc lệch ngày/đêm giữa các component.

Reliability & At-Least-Once Backend Architecture / Distributed Reliability

Transactional Outbox Relay Pattern

Bản Chất Kỹ Thuật (What it is)

Các Domain Service ở Core Backend tuyệt đối không gọi gửi Email/SMS/Push trực tiếp hoặc import worker. Mọi biến động nghiệp vụ được ghi nhận đồng thời thành bản ghi sự kiện vào bảng outbox_events trong cùng một Database Transaction. Mục Đích & Rationale (Why we use it)

Bức Tranh Tổng Thể Kiến Trúc Frontend (`quote-generator`)

Frontend được xây dựng trên Next.js 14+ App Router, phân tách tuyệt đối giữa Tầng Hiển thị Khách hàng (5-Layer Display System) và Tầng Không gian Làm việc của Nhân viên (Quotation Workspace, Content Studio, Staff Tools).

Sơ Đồ Dòng Chảy Dữ Liệu & Hợp Đồng Phân Tầng Frontend

TẦNG 1: RSC & Display
5-Layer Display System

Server Component render siêu tốc, độc lập 100% với Admin code.

  • • Theme Tokens
  • • View Modes (Desktop/Mobile/PDF)
  • • Atoms -> Molecules -> Sections
TẦNG 2: Workspace & Facades
State Facades & Hooks

Single-pass state transformation cho React form inputs.

  • • prefillEngine.ts

Canonical Adapters

Chuyển đổi 2 chiều không làm biến dạng schema gốc.

  • • tripAdapter.ts

TẦNG 4: Pure Reconcilers
Domain Invariant Engine

Hàm thuần túy, 0 React dependencies, bảo vệ bất biến.

  • • tripReconciler.ts
  • • staysReconciler.ts
  • • pricingReconciler.ts
1. Server-First & Client Islands

Mọi trang brochure công khai là Async RSC. Leaflet Map và Rich Text TipTap được bọc bằng dynamic import với ssr: false giúp giảm 70% bundle client.

2. Typography SSOT Guard

Cấm tiệt viết class Tailwind text/font tùy tiện trong display/. Toàn bộ phải đi qua semantic token typo-* trong config/typography.ts.

3. Zero useEffect Data Drift

Không dùng useEffect để đồng bộ state phái sinh (ngày kết thúc, đêm khách sạn, đơn giá). Tất cả tính toán tập trung trong render hoặc gọi qua Pure Reconciler.

B1 · CRITICAL SPOF

In-Memory SSE Broadcaster — khóa chặt vào 1 instance

Phát nổ tại: ~5K kết nối đồng thời / 1 process
⚠️ Cơ chế hiện tại & lý do nghẽn

SSEBroadcaster là singleton per-process (_global_broadcaster) giữ dict[email, set[asyncio.Queue]] trong RAM của đúng 1 process, publish bằng put_nowait vào queue không giới hạn maxsize (zero backpressure). Chạy 2+ replica notification-service sau load balancer: event publish vào instance A không bao giờ tới user đang stream trên instance B. Restart process = mất toàn bộ subscribers. Mỗi connection giữ vòng lặp wait_for(queue.get(), timeout=20s) + heartbeat ping — hàng nghìn sales/client mở đồng thời sẽ bão hòa 1 uvicorn worker duy nhất.

4.3 — 7 Trụ Cột Blueprint Tiến Hóa (Enterprise Evolution Pillars)

P1

Distributed Event Bus cho Outbox & Notification Fan-out

Giữ nguyên bảng outbox_events (hợp đồng bất biến), thay daemon HTTP polling bằng relay mỏng đẩy vào Redis Streams (giai đoạn 1) rồi Kafka (giai đoạn 2 khi >10K events/s). Consumer groups cho phép N notification worker cùng kéo không trùng lặp; DLQ + replay theo offset thay vì retry-count cột DB. Giải quyết: B2. Idempotency key hiện có của delivery worker được giữ nguyên làm chốt chống double-send.

P2

Distributed PDF Rendering Worker Fleet

Tách render_react_pdf_bytes khỏi API process: publish tạo pdf.jobs vào queue (Celery/BullMQ, hoặc Temporal nếu cần workflow durable), worker pool riêng chạy Chrome pool được warm sẵn, autoscale theo queue depth, giới hạn 1–2 render/worker. Kết quả upload thẳng Object Storage; API chỉ trả job status + bắn event quotation.publication.completed qua bus (client nhận qua SSE như hiện tại). Giải quyết: B3. Bonus: pre-render PDF ngay khi publish thay vì đợi người dùng bấm Export.

P3

Database Scaling: PgBouncer + Read Replicas (CQRS) + Partitioning

Ba lớp theo thứ tự ROI: (1) PgBouncer transaction pooling — chặn đứng bùng nổ connection khi scale API fleet; (2) Read Replicas + CQRS routing — toàn bộ đọc brochure công khai, catalog, danh sách workspace đi replica; chỉ ghi (costing, facts, publication) chạm primary. SQLAlchemy đã tách sạch Repository layer nên chỉ cần bind 2 engine read/write; (3) Partitioning outbox_events theo thời gian (drop partition cũ thay vì DELETE) và tenant partitioning khi multi-brand B2B mở rộng. Patroni/managed HA cho failover < 30s. Giải quyết: B5.

P4

Multi-Tier Caching L1 / L2 / L3 + Event-Driven Invalidation

L1: in-process LRU (Next.js/FastAPI) cho theme tokens, brand config, content budgets — TTL ngắn 30–60s. L2: Redis cho resolved brochure payload theo slug@revision — key bất biến theo revision nên không bao giờ stale. L3: Cloudflare edge cache trang /q/[slug] với stale-while-revalidate. Khi re-publish: event publication.completed trên bus kích hoạt webhook purge đúng URL (nối vào hook release_cache_urls có sẵn) — invalidation tức thì, không đợi TTL. Giải quyết: B6; brochure viral được hấp thụ 99% tại edge.

P5

AI Gateway Layer: Rate Limit · Semantic Cache · Fallback · Circuit Breaker

Chèn 1 lớp gateway ngay sau llm_client.get_model() (điểm khởi tạo duy nhất — vị trí chèn hoàn hảo): (1) Token-bucket rate limiter per-tenant + global, hàng đợi công bằng thay vì 429 storm; (2) Semantic cache (Redis vector): facts-hash + prompt-version làm key chính xác, embedding similarity làm key mềm — draft trùng lặp trả từ cache trong 50ms, tiết kiệm 60–80% chi phí; (3) Fallback model chain (primary DeepSeek → OpenAI đã có sẵn — nâng thành policy có health check); (4) Circuit breaker: provider lỗi liên tiếp thì mở mạch, queue job lại thay vì fail-closed thẳng vào mặt user. Giải quyết: B4. Fail-closed validation của Pydantic output giữ nguyên — chỉ thay đổi cách chịu tải phía trước.

P6

SSE Horizontal Fan-out: Redis Pub/Sub Backplane

Giữ nguyên giao diện SSEBroadcaster.subscribe/publish (frontend hook useNotifications không đổi 1 dòng), thay ruột: publish đẩy vào Redis Pub/Sub channel notif:{email}; mỗi instance notification-service subscribe Redis và bơm vào asyncio.Queue local của các connection nó đang giữ. Kết quả: user cắm vào bất kỳ replica nào cũng nhận đủ message, không sticky session, restart 1 instance chỉ làm client auto-reconnect (đã có sẵn trong hook). Khi vượt 100K streams, nâng cấp lên managed push tier (Pusher/Ably-style) mà không đổi contract. Giải quyết: B1.

P7

Zero-Downtime & Observability: OTel · Prometheus · Grafana · DLQ Recovery

Không đo được thì không scale được: (1) OpenTelemetry distributed tracing — trace ID sinh tại edge, truyền qua Gateway → FastAPI → Bus (header trong event envelope) → Worker → SQL, nhìn thấy trọn đường đi 1 lượt publish; (2) Prometheus metrics: outbox lag, queue depth, SSE connection count, LLM token spend/tenant, 409-conflict rate, replica lag; (3) Grafana dashboards + SLO burn-rate alerts gắn với error budget 99.99%; (4) DLQ Recovery Engine: event chết được lưu kèm nguyên nhân, UI replay chọn lọc — biến sự cố thành thao tác vận hành 1-click; (5) Rolling deploy + health/readiness probe từng fleet — không còn khái niệm "restart là mất SSE".
